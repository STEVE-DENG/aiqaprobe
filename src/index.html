2026.10.26 工程 抓包只是证据链的起点

抓到一条失败请求，只能说明问题发生过，不能说明问题为什么发生。 有用的证据链至少包含触发条件、请求上下文、模型或工具状态，以及一次可重复的复现。

所以抓包工具不应该停在“看见”。它还要帮助人固定范围、标记证据、重放失败， 最后生成一条能够进入回归集的用例。

trace / replay / evidence
2026.10.25 Agent Agent 的失败，不能只记一个分数

多步任务的最终答案只是结果，不是过程。工具选择错误、参数漂移、上下文丢失、 循环超时，都可能得到同一个“任务失败”的标签。

先给失败分类，再比较不同版本，才知道模型到底变好了，还是只是换了一种坏法。

failure taxonomy / trace
2026.10.24 评测 AI 评测不是刷榜

榜单给方向，业务给答案。好的 eval 不只要算出一个分数，还要能解释模型为什么失败、 下次怎样确认它没有复发。

评测集、评分器和统计波动需要一起设计。没有失败切片的分数，很难支持真实决策。

eval set / rubric / baseline
2026.10.23 Agent 为什么 Skill 需要人工批准

成功轨迹不等于可复用能力。一次任务成功，可能依赖偶然的页面状态、 不稳定的坐标，或者模型恰好猜对了下一步。

人工批准的价值不是增加流程，而是检查这段路线是否真的被理解、是否值得被再次执行。

skill / approval / replay
2026.10.22 工程 从一次失败到一条回归

一条好的回归用例，应该保留触发失败的上下文，又收缩到可以稳定重放的最小范围。 先固定证据，再修正判断，最后才让门禁上场。

regression / evidence
2026.10.20 评测 把幻觉当缺陷分类

幻觉不是一种单一错误。它可能是检索缺失、推理跳步、工具误用， 或者评价标准本身不清。先分类，再谈修复。
